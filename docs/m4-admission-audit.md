# M4 准入与完整 ODE 审计职责复核

日期：2026-11-15（Asia/Shanghai）。本轮只读核对原协议、历史验收和当前实现，不修改历史证据、验收阈值或算法。**现有证据仍不支持 M4 准入。** [Mac 验收](../results/m3-continuation/acceptance.json)的 26 项证据检查通过，但四个模型／目标组合的效率资格均为假；检查通过不等于准入通过。

## 离线真值与运行时审计的职责

[基准协议](benchmark-protocol.md) §5 明确：统一离线参考生成不计入候选耗时；候选运行时依赖的影子参考步必须计时。两者按数据用途区分，不能按文件名或是否提前缓存区分。

1. **统一离线资格真值**从原登记初值独立求原完整 ODE；需要收紧与另一算法核对，差异低于最严格目标的 5%。其作用是外部评价实际浓度、速率、净通量和参考可靠性，不能影响候选状态、候选步长或接受决定。模型公共网格上的离线真值生成可排除在各方法运行时间之外。
2. **运行时逐候选审计**从该候选的实际起点出发，独立求原完整非线性 ODE，比较候选输出并参与接受／拒绝。历史 M3 审计中点／终点，Mac 续作补上每个请求输出及四分点。其求解、必要评分、初始化及依赖工作全部属于候选成本；不能使用离线原始轨迹上的不同起点来代替。
3. **审计容差的资格校准**检验运行时审计自身是否足够精确。`MacroSplit.integrate` 目前每候选调用一次 `full(..., c.audit_rtol)`，不是每次求两条完整 ODE。近期 [审计预算实验](m3-audit-budget.md)的 `1e-12/1e-11` 双解是该实验预登记策略，不是原 M4 协议要求每个候选执行双解的硬编码条件。原协议仍要求可信收紧和完整审计；若新架构只在校准阶段成对收紧，必须独立验证误差预算及适用域，并完整保留运行时逐候选完整核验。

因此可以研究较低工作量的完整审计、合格内部容差及合法跨步资源复用。每次改变都应独立预登记，在原 .05 开发预算、独立旧真值和收紧检查下重新验证，失败保留。不能凭内部求解器的 `rtol`、两条近似解相互接近或局部有限样本零漏检，就声称全路径可靠；也不能将参与控制的已计算双解改标离线成本。

现有审计预算表的负余额仅否定该实现的高精度双解架构。即使单条审计获得正预算，仍缺真正分裂内核、输出／收支、分组、估计、失败及回退的全部端到端成本。两类结论都不能从局部冷起步直接推广到完整窗口。

## 新准入判定器需要保留的证据检查

现有 `metabolism/m3_continuation.py:audit` 是一批冻结实验的验收器，正确给出现有 `not_admitted`，不宜将它当作可直接接收任意新记录的通用入口。以下是新通用判定器应明确验证的项目，不表示历史实验已出现造假或错误准入。

- 按完整 `(model, target, method/config fingerprint, platform/environment fingerprint)` 分组正式重复；校验重复编号唯一、集合完整，预热单列。现有实现按模型／目标收集后仅检验 `len == 7`，若输入任意混合记录，会把不同配置或重复编号算作一组。基线同样需要唯一编号与固定配置。
- 对四个必需组合逐项输出失败原因；缺记录、缺键、NaN、无合格基线均应拒绝，不让空集合的 `all(...)` 或默认零残差制造通过。适用开放账本的缺失字段应为缺证据；大模型未配置的开放账本标为“不适用”，不伪造测量零值。
- 对每条正式候选核验原模型、初值、窗口、公共网格、尺度和参考指纹。参考预算、实际误差和结构指标从保存曲线重新计算，并与每个重复对应；现有验收器主要对探针／基线 `repeat == 0` 的保存曲线重算，候选正式重复路径尚未实际产生，后续不能只信任任意输入的 `metrics.passes`。
- 依据最终已提交、不重叠的接受反应分裂区间重新计算覆盖时间／完整窗口长度，核验起点、终点、拼接与完整系统区间。撤销的接受、失败候选、全系统预测和回退均排除；不能只信任输入 `split_coverage` 数字。
- 将每个接受区间关联到独立完整 ODE 审计、请求输出与登记内部检查点；验证审计预算、来源及非候选注入。拒步／检查点恢复需有原子回滚证据，不能只检查最终保留轨迹。
- 校验运行时间正且有限；逐条确认计时边界涵盖所有运行时依赖工作，setup 单列且双方口径一致。中位数及 IQR 从完整正式数组重算；只有全部硬门通过后计算可用于准入的速度比。
- 成熟基线必须有登记容差搜索和相同优化机会，按相同实际精度／结构要求选择最快合格配置；完整包装 `full-only` 对照只是开销诊断，不能自动替代最快成熟基线。历史 Mac 基线可作历史比较，不能与新机器负载下计时拼接成正式结论。
- 输出 `evidence_integrity`、四组合的 `correctness/coverage/repeats/timing/efficiency` 及总 `M4_admission`，分别指出数据未完整和科学门槛失败；附输入／源码／环境指纹。缺一组合不得以其他组合平均达标。

建议用无真实积分的最小合成记录测试判定器的失效边界：7 个相同编号、混配方法、缺净通量、缺开放账本、空审计、伪覆盖、NaN 时间、未完成窗口、单一模型缺档，以及一个具备完整证据的合格记录集。该测试针对错误准入风险，不需要重跑历史重型实验。

本轮新增 [只读状态脚本](../metabolism/m4_admission.py)与 [风险回归检查](../research/test_m4_admission.py)，按现有 Mac 数据结构重算四组合、唯一重复编号、逐重复指标和接受分裂区间。四项回归测试覆盖空／重复／混配记录、失败及缺指标、虚构覆盖／无反应分组的完整预测器、缺输入拒绝。脚本重新核对两代验收 SHA-256，结果为证据完整性通过、四组合均无合格正式候选重复，保存于 [最新状态](../results/m4-admission/state.json)。它要求原独立验收同时通过，只能聚合当前历史证据；上述针对未来新方法的全曲线重新求解／评分职责仍由该方法的独立验收器承担。

```bash
bash scripts/run-macos.sh -m unittest research.test_m4_admission
bash scripts/run-macos.sh -m metabolism.m4_admission --write
```

## 继续顺序

首先完成新的审计容差／收紧校准，使用同批完整成熟对照和全部实际评分成本判断是否有正预算；单条与双条运行时策略分别报告，不能相互替换。若不存在正预算，保留否定结果，继续寻找有明确假设和成本边界的完整审计实现；不得以移除安全检查作为晋级路线。

若存在正预算，再把实际接受的反应分裂及连续输出接到事务控制中，先验证自生成短路径、早期状态、切换、扰动、累计误差及收支，随后以同机强基线做端到端开发成本筛查。只有两模型均有前景，才投入原完整窗口和冻结配置七次正式重复。当前没有新候选满足这条顺序的最后两步，也未实施 PE。
